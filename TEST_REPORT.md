## 1. Introduction

Pawang AI predicts flood risk per kecamatan (44 areas of DKI Jakarta) and shows it on a map. The system has four parts:

| Part | Folder | What it does |
|---|---|---|
| Prediction model | `Pawang_Prediction_Model/` | data pipeline, logistic model (`rainfall_only` and `full`), calibration, thresholds |
| Backend | `backend/` | FastAPI; tools (Open-Meteo, BPBD water level); Agent 1 (data fetch), Agent 3 (freshness), Agent 2 (failure handling); advice writer; guardrails; cache; audit log |
| Frontend | `frontend/` | Next.js + Leaflet map; proxy routes `/api/v1/*` |
| Evaluation | `backend/eval/` | system evaluation against recorded floods, agent drills, agent capability check |

Purpose of this report: record what was tested, how, with what result, and what is still open. Related documents:
[Pawang_Prediction_Model/TEST_PLAN.md](Pawang_Prediction_Model/TEST_PLAN.md) (model test plan),
[Pawang_Prediction_Model/TEST_RESULTS.md](Pawang_Prediction_Model/TEST_RESULTS.md) (full model result tables, regenerated by this run).

## 3. Test design

| Area | Items tested | Approach |
|---|---|---|
| Data (D) | positives per year, duplicates and gaps, reproducible rebuild, rainfall-cache gap check, flood-date parsing | rebuild from raw files and compare with the committed table |
| Model quality (M) | skill over random, over a rainfall baseline, stability across years, leakage, calibration, thresholds, algorithm choice | cross-validation by year, shuffled-label control |

## 5. Test procedures

Run from the repository root. Python commands use the project's installed environment.

```bash
# 1. Model (about 30 s each)
cd Pawang_Prediction_Model
python -m pytest -q                       # 37 tests
python tests/run_test_plan.py             # 23 checks, rewrites TEST_RESULTS.md

# 2. Backend
cd ../backend
python -m pytest -q                       # 61 tests, no network
QWEN_ENABLED=false python -m eval.check_agents      # 28 agent checks
python -m eval.evaluate system --year 2020          # about 50 s
QWEN_ENABLED=true  python -m eval.evaluate agents --repeats 1   # needs Ollama with qwen3.5:4b

# 3. Frontend
cd ../frontend
npm run typecheck && npm run lint && npm test
npx next build

# 4. Live end to end (real internet)
cd ../backend
PAWANG_DATA_MODE=live QWEN_ENABLED=false PAWANG_TMA_STORE=$TEMP/tma_check.csv \
  python -m uvicorn app.main:app --port 8011 &
curl localhost:8011/api/v1/health
curl "localhost:8011/api/v1/heatmap?time=1h"
curl "localhost:8011/api/v1/heatmap?time=24h"
curl "localhost:8011/api/v1/analysis?grid_id=menteng&time=5h"
curl -w "%{http_code}" "localhost:8011/api/v1/heatmap?date=2020-02-31"
# stop the server afterwards
```

`.github/workflows/ci.yml` runs the backend tests and the frontend checks on every push and pull request.

What this means:

- **The pipeline is reproducible.** Rebuild and retrain give identical tables, metrics and thresholds (D2b, G3, G3b).
- **The model has real but modest skill.** It beats chance on every fold (M1) and shuffled labels remove the skill (M4), so no leakage.
  It does not beat the 3-day-rainfall ranking in every year (M2: 6 of 8 folds). 2019 is the weakest year.
- **Probabilities are compressed.** Calibration passes on Brier score, but the model ranks better than its percentages
  read (see `TEST_RESULTS.md`, M5 reliability table), so the UI shows low percentages even on a day when many kecamatan flood.
- **Thresholds depend on the validation year** (M6): `high` for the full model ranges from 3.3% to 10.2%.
- **`full` rests on 3 CV folds only** (M3), so its stability claim has little evidence.

### 9.5 Known limits of this testing

- **The full model has never run in live mode on real data.** It needs about 2 days of BPBD history (`PAWANG_TMA_POLL_S=1800`). Only fixtures cover it.
- **Qwen is untested end to end** (I-5). The Qwen path is covered by mocked tests only; the advice text in the UI is template text.
- Today's water level is the maximum so far today, while the model trained on whole days. This bias is not measured.
- Training rainfall is reanalysis and inference uses forecasts. No forecast archive exists, so this mismatch is not tested.
- Flood labels are incomplete (unreported floods count as 0), so precision is probably understated.
- Not re-run on 2026-11-12: the manual UI and Next.js route checks (4.7) and the headless-Chrome screenshot. The screenshot predates the
  `MapDashboard.tsx` change in 2.1.1, so the current UI has no screenshot.
- No mobile, accessibility, load or security testing. A review of the code found open issues in these areas that no test covers yet
  (cache of failed lookups, unbounded request variety, slow-LLM thread exhaustion).
- The BPBD scraper depends on one page layout. The parser fails loudly if the table changes; the test uses a snapshot from 2026-11-08.

4. Start Ollama with the expected Qwen model and run `eval.evaluate agents` and `eval.check_agents` with Qwen on.
5. Decide the user-facing risk labels and thresholds with the team (M5 and M6).
